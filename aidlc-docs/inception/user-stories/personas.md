# Personas（ペルソナ）

**プロジェクト**: 藝大 音響教育アプリ（「音」から始まる、耳のためのアプリケーション）
**作成**: 2026-07-15 / AI-DLC User Stories（Part 2）
**更新**: 2026-07-30 / 役割名ベースへ整理（個人名・個人予定は記載しない）
**入力**: `../requirements/requirements.md`

## P1. こども/学習者（プレイヤー） — 「みみ」

| 項目 | 内容 |
|---|---|
| アーキタイプ | アプリを実際に使い、録音・加工・ゲーム・音図鑑・音づくりで遊ぶエンドユーザー。 |
| 代表像 | 7〜12歳の子ども（保護者/教育者の見守りあり）。音や声で遊ぶのが好き。 |
| 目標（Goals） | 自分の声/音を録って変化させて楽しむ。音を聴き分ける。制作側の音を発見し、組み合わせて新しい響きを作る。 |
| 動機（Motivations） | 遊びの延長で「きく力」を育てたい。進めるほど使える音が増える楽しさ。正解演出（カエルへの進化）が嬉しい。 |
| 技術習熟度 | 低〜中。直感的なタップ/ドラッグ操作を好む。 |
| 利用文脈 | 自宅や教室。縦・横どちらでも持つ。オフライン。短時間の反復利用。展示会場での試用も含む。 |
| 痛み・ニーズ | 難しい言葉/複雑UIは離脱要因。端末サイズ差でも崩れないこと。ノッチ等でボタンが隠れないこと。 |
| プライバシー | 生年・ニックネーム・写真・メモは端末内のみ。外部送信されない安心感が必要。 |
| 関連ストーリー | US-REG-01, US-REC-01〜03, US-COL-01〜04, US-THEME-01/02, US-GAME1-01〜05, US-LIB-01/02, US-CREATE-01〜04, US-TECH-01/02 |

## P2. 企画・デザイン担当

| 項目 | 内容 |
|---|---|
| アーキタイプ | 企画・画面・音素材・お題・解除条件・音図鑑分類を用意/更新する運用者。 |
| 代表像 | 企画・教材・見た目調整を担う役割。実装の詳細は他役割に委ねる。 |
| 目標（Goals） | weekly theme・音図鑑カタログ・解除条件表・ゲームパラメータを差し替え可能に保つ。UI の余白・配置・配色・素材を仕上げる。 |
| 動機（Motivations） | 大きな作り直しなく内容を更新したい。コードを触らず（または最小限で）調整したい。 |
| 技術習熟度 | 中（企画・デザイン寄り）。ScriptableObject / Prefab / 素材差し替えは可能。 |
| 利用文脈 | 企画・素材準備＋UI詳細調整。枠組み提供後の見た目仕上げ。 |
| 痛み・ニーズ | お題・パラメータ・UI見た目・音素材が「調整可能な構成」であること。 |
| 関連ストーリー | US-THEME-01/03, US-GAME1-04, US-LIB-01, US-TECH-07/08/09 |

## P3. 基盤・統合担当

| 項目 | 内容 |
|---|---|
| アーキタイプ | 共通サービス、画面遷移、保存、アンロック基盤、シーン統合、ビルドを担当する開発者。 |
| 代表像 | Unity（C#/URP/uGUI）で共通基盤と統合を担う役割。 |
| 目標（Goals） | 共通IFを安定させ、端末横断で動作する枠組みと展示用試用ビルドを提供する。UI枠組みまで作り、見た目は企画・デザインへ渡す。 |
| 動機（Motivations） | 暫定仕様に耐える設計、回帰を抑える変更管理、再現性の高いシーン操作。 |
| 技術習熟度 | 高（Unity/C#、ビルド、Git）。 |
| 利用文脈 | 開発環境。Unity MCP 経由のシーン操作。feature ブランチ＋PR。 |
| 痛み・ニーズ | モジュール境界の曖昧さ、共通IFの破壊的変更、容量・性能の未計測。 |
| 関連ストーリー | US-TECH-01〜09, US-LIB-03, US-CREATE-03, US-COL-04 |

---

## P4. 音響実装担当

| 項目 | 内容 |
|---|---|
| アーキタイプ | レイヤー再生、加工、レシピ再生／WAVE書き出しなど音響処理を担当する開発者。 |
| 代表像 | 音を使ったゲーム／DSP に関心のある実装役割。合意済み Audio/Storage IF 内で作業する。 |
| 目標（Goals） | 2音の組み合わせ・加工・試聴と、レシピ再生／必要時の書き出しを安定動作させる。 |
| 動機（Motivations） | 音の体験品質を高めつつ、モバイル性能と容量を守る。 |
| 技術習熟度 | 高〜中（音声処理寄り）。 |
| 利用文脈 | 独立モジュール／サービス内での実装。共通IFの変更はレビュー経由。 |
| 痛み・ニーズ | IF未合意での着手、高品質DSP期待とモバイル制約のギャップ。 |
| 関連ストーリー | US-CREATE-01〜04, US-LIB-03, US-TECH-09 |

---

## P5. ゲーム実装担当

| 項目 | 内容 |
|---|---|
| アーキタイプ | 追加ミニゲームをシーン・ルール・UI・音声連携・テストまで縦割りで担当する開発者。 |
| 代表像 | 1本のゲームを独立モジュールとして完成させる役割。 |
| 目標（Goals） | 追加ゲームを共通基盤に接続し、進行条件を音図鑑アンロックへ渡せるようにする。 |
| 動機（Motivations） | 他モジュールと衝突せず、明確な完了条件で進めたい。 |
| 技術習熟度 | 中〜高（Unity/ゲームロジック）。 |
| 利用文脈 | `Geidai.GameN` 相当の独立アセンブリ／シーン。 |
| 痛み・ニーズ | 共通進行APIの未定義、素材ID参照の不統一。 |
| 関連ストーリー | US-GAME1-*, US-LIB-02/03, US-TECH-09, FUT-01 |
