## P1. こども/学習者（プレイヤー） — 「みみ」

| 項目 | 内容 |
|---|---|
| アーキタイプ | アプリを実際に使い、録音・加工・ゲームで遊ぶエンドユーザー。子どもを中心に、「聴く」ことに興味のある学習者全般を含む。 |
| 代表像 | 7〜12歳の子ども（保護者/教育者の見守りあり）。音や声で遊ぶのが好き。 |
| 目標（Goals） | 自分の声/音を録って、変化させて楽しむ。お手本の音と自分の音を聴き分けられるようになる。集めた音を後から聴き返す。 |
| 動機（Motivations） | 遊びの延長で「きく力」を育てたい。自分だけの音コレクションを作りたい。正解演出（カエルへの進化）が嬉しい。 |
| 技術習熟度 | 低〜中。細かい設定や文字入力は苦手。直感的なタップ/ドラッグ操作を好む。 |
| 利用文脈 | 自宅や教室。スマホ/タブレットを縦・横 どちらでも持つ。オフライン環境でも使う。短時間（数分）の反復利用。 |
| 痛み・ニーズ | 難しい言葉/複雑UIは離脱要因。視覚に頼らず音中心でも遊べること。端末サイズが違っても表示が崩れないこと。ノッチ等でボタンが隠れないこと。 |
| プライバシー | 生年・ニックネーム・写真・メモは端末内のみ。外部送信されない安心感が必要。 |
| 関連ストーリー | US-REG-01, US-REC-01〜03, US-COL-01〜04, US-THEME-01/02, US-GAME1-01〜05, US-TECH-01/02 |

## P2. 企画・コンテンツ運用者 — 「Sさん」

| 項目 | 内容 |
|---|---|
| アーキタイプ | 企画・画面・音素材を担当し、お題やゲーム内容を用意/更新する運用者。初心者制作者としての視点も持つ（＝簡潔な運用手段を必要とする）。 |
| 代表像 | 藝大側の企画担当（須藤研の文脈）。音響教育・「きく」体験の設計者。 |
| 目標（Goals） | weekly theme のお題を用意/差し替えする。ゲームのお手本音や難易度方針を反映する。子ども/学習者に届く体験を継続的に運用する。 |
| 動機（Motivations） | 研究会後に確定する仕様（出題数/音域/音長/難易度）を、大きな作り直しなく反映したい。制作の専門知識が浅くても運用できる構造がほしい。 |
| 技術習熟度 | 中（企画・デザイン寄り、実装は前本に依頼）。データ差し替えは可能だが、複雑なビルド作業は避けたい。 |
| 利用文脈 | 企画・素材準備フェーズ。前本と分担しながら、お題テキストや音素材を提供・更新。 |
| 痛み・ニーズ | お題やパラメータが「差し替え可能な構成」であること。暫定仕様が更新前提で、変更に強い設計であること。 |
| 関連ストーリー | US-THEME-01/03, US-GAME1-04, US-REG-02（識別方針）, US-TECH-05（運用フロー） |

## P3. 実装・技術担当 — 「前本」

| 項目 | 内容 |
|---|---|
| アーキタイプ | 実装・技術設計・保守を担当する開発者。既存 Unity 実装のエンハンス/整理と、非機能（レスポンシブ/SafeArea/堅牢性/テスト）の担保を行う。 |
| 代表像 | Unity（C#/URP/uGUI）開発者。AI-DLC で要件→設計→実装を進める。 |
| 目標（Goals） | 企画を破綻なく実装し、端末横断で安定動作させる。録音実装を一本化し、不要コードを整理して保守性を高める。データ破損を防ぐ。 |
| 動機（Motivations） | 暫定・更新前提の仕様に耐える設計。回帰を抑える軽量な変更管理とテスト。シーン操作を再現性高く行いたい。 |
| 技術習熟度 | 高（Unity/C#、DSP、ビルド、Git）。 |
| 利用文脈 | 開発環境。Unity 標準 MCP サーバー（unityMCP）経由でシーン/GameObject/プレハブを操作。Git ブランチ＋PR で変更管理。 |
| 痛み・ニーズ | 録音実装の重複（VoiceRecordingSection と RecorderWithEffects）や不要コード（Scean.cs 等）による保守負荷。CanvasScaler が横基準で縦対応が不十分。SafeArea 未対応。テスト不足。 |
| 関連ストーリー | US-TECH-01〜06, US-REC-03（保存仕様）, US-COL-04（永続化/堅牢性）, US-GAME1-05（リアルタイム加工） |
