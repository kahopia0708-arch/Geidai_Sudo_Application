# U4 Persistence/Collection — Business Rules（業務ルール）

**ユニット**: U4 Persistence/Collection
**作成**: 2026-07-15 / AI-DLC CONSTRUCTION / Functional Design（Part 2）
**技術非依存**: 具体 API・スクロール仮想化・写真ピッカー実装・シーン配線は NFR Design / Code Generation。

> 記法: `BR-COL-xx`。各ルールは US-COL/US-TECH-06・FR-09〜12・NFR-04/05/07 にトレース。

---

## 1. 一覧・データソース（US-COL-01 / Q1=A）
- **BR-COL-01**: 一覧の対象は**新形式のみ**（`sounds/{id}.wav`＋`{id}.meta.json`）。旧 `MySoundCollection` 形式は対象外（移行しない）。
- **BR-COL-02**: 一覧は **meta 基準**で構築する（`*.meta.json` を走査）。
- **BR-COL-03**: 並び順は**作成日時（`createdAtIso`）の降順**（新しい順）を既定とする。
- **BR-COL-04**: 一覧項目の表示名は `title`。空なら `createdAtIso` の日付表記にフォールバック（BR-COL-11）。

## 2. メタデータ（US-COL-02 / FR-10 / Q2=A）
- **BR-COL-10**: `SoundClipMeta` は後方互換で拡張（`title`/`photoFileName`/`memo`/`nickname` を追記）。既存フィールドは不変。旧 JSON は欠損＝既定値で読む。
- **BR-COL-11**: `title` 未設定（空）時の表示は**作成日付**（例: `2026/07/15`）。保存はあくまで空のまま（表示時フォールバック）。
- **BR-COL-12**: `title` は前後空白を trim。**最大長を設ける**（目安 40 文字・確定は NFR Requirements）。改行不可。
- **BR-COL-13**: `memo` は任意。**最大長を設ける**（目安 200 文字・確定は NFR Requirements）。
- **BR-COL-14**: `nickname` は保存時にプロフィールの値を写す（編集画面では基本読み取り）。プロフィール未登録なら空可。
- **BR-COL-15**: メタ編集の保存は**原子的置換**（BR-COL-50）。失敗時は既存 meta を壊さない。

## 3. 写真（US-COL-02 / Q4=A / NFR-04）
- **BR-COL-16**: 写真は任意。保存する場合 `sounds/{id}.photo.<ext>`（jpg/png）とし `meta.photoFileName` で参照。
- **BR-COL-17**: 写真取得は抽象（`IPhotoPicker`）。U4 は枠組み＋スタブ（表示/差し替え/削除フローは実装、実機ピッカー結線はフォローアップ）。
- **BR-COL-18**: 写真・メモ・ニックネームは**個人情報**。端末外へ送信しない・ログへ出さない（NFR-04 / SECURITY-03）。
- **BR-COL-19**: 写真差し替えは原子的コピー後に旧写真を置換/削除。写真削除は `photoFileName` を空にしファイルを削除（欠損は無視）。

## 4. 破損・欠損・空（US-COL-04 / US-TECH-06 / Q3=A）
- **BR-COL-20**: meta が破損（パース不可/null）なら**安全にスキップ**し、他項目は正常表示（クラッシュしない）。
- **BR-COL-21**: 対 `wav` が欠損した meta は**スキップ**（対の原則）。写真欠損は項目を無効化しない（写真なし表示）。
- **BR-COL-22**: 有効項目 0 件、またはディレクトリ無し/初期状態は**空状態**を表示（例外にしない）。
- **BR-COL-23**: 破損スキップ件数はデバッグ用途で把握可能にする（ユーザーには通常見せない）。ログに PII を含めない。

## 5. 視聴・再生（US-COL-01 / Q7=A）
- **BR-COL-24**: 項目タップで視聴。**保存エフェクト（`SoundEffectSettingsData`）を非破壊で再適用**して再生（録音時と同じ聴こえ）。生 wav 自体は変更しない。
- **BR-COL-25**: 再生失敗（ファイル欠損/破損/デコード不可）は `Result` で通知し、一覧は維持（該当項目は必要に応じスキップ扱い）。
- **BR-COL-26**: 別項目の再生・停止時は現在の再生を停止してから切り替える（多重再生しない）。

## 6. 絞り込み・検索（US-COL-03 / Q5=A）
- **BR-COL-30**: 検索キーワードは trim ＋ 大文字小文字/全半角を実用的に無視して比較。対象は `title`/`memo`/`nickname` の**部分一致（含む）**。
- **BR-COL-31**: 月別絞込は `createdAtIso` から `YYYY-MM` を導出して一致判定。無効/欠損日付の項目は月別絞込時に**非該当**として扱う（一覧全体では表示）。
- **BR-COL-32**: 絞込（月）と検索（キーワード）は **AND** 合成。
- **BR-COL-33**: フィルタは**純粋関数**（入力＝項目リスト＋条件、出力＝フィルタ済みリスト、副作用なし）としテスト容易化（PBT/単体候補）。
- **BR-COL-34**: 該当 0 件は**空状態**（「みつからなかったよ」等）。条件解除で復帰。

## 7. 削除（US-COL-01 / Q6=A / NFR-05）
- **BR-COL-40**: 削除は**確認ダイアログ**（`ConfirmDialog`・既定＝いいえ）を必須とする（誤操作防止）。
- **BR-COL-41**: 承諾で該当の `wav`＋`meta`＋`photo` を**一括削除**。欠損ファイルは無視（ベストエフォート）。
- **BR-COL-42**: 削除の途中失敗は `Result` で通知。可能な範囲で削除を進め、**一覧は再読込で整合**を取る。
- **BR-COL-43**: 削除後は一覧・絞込結果を即時更新。空になれば空状態へ。

## 8. 永続化・原子性（US-TECH-06 / NFR-07 / Q3=A）
- **BR-COL-50**: 書込（新規/更新）は「一時ファイルへ書込→成功後に本ファイルへ**原子的置換**」で行い、途中失敗で既存データを壊さない。対象＝`profile.json`/`{id}.meta.json`/`{id}.wav`/写真。
- **BR-COL-51**: U3 `SaveSound`（wav→meta・失敗時 wav 削除）を本モデルの原子的置換へ**強化**（シグネチャ後方互換）。wav→meta の対整合を保証。
- **BR-COL-52**: すべての I/O 失敗は `Result`（理由コード）で返し、`ErrorPresenter` で子ども向けに平易通知（クラッシュしない）。
- **BR-COL-53**: 重要度分類＝Rec/Collection = **Critical**（RESILIENCY-01）。
- **BR-COL-54**: すべてのデータは端末ローカルのみ（`Application.persistentDataPath`）。外部送信なし（NFR-02/04）。

## 9. UI ハンドオフ・レスポンシブ（US-TECH-07 / NFR-11/12）
- **BR-COL-60**: 一覧は Anchor/レイアウトグループで構成し、**固定 px 依存を排除**（例: 旧 `itemWidth 850px` のような固定値を相対指定へ）。縦横両対応・各画面サイズで破綻しない。
- **BR-COL-61**: 見た目（配色/アイコン/余白/モチーフ/文言）は S さんが調整できる余地（差し替え可能素材・柔軟レイアウト）を残す（US-TECH-07）。SafeArea を画面ルートに適用（NFR-12）。
