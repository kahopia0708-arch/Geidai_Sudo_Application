# Performance Test Instructions（性能テスト手順）

**プロジェクト**: 藝大 須藤さんアプリ
**作成**: 2026-07-16 / AI-DLC CONSTRUCTION / Build and Test

## Purpose（目的）
モバイル端末で子どもが快適に使える「体感即時・なめらか」な性能を検証する。サーバー負荷は無い（オフライン）ため、**端末上のフレームレート・応答遅延・メモリ/GC・I/O 時間**を対象とする。

---

## Performance Requirements（性能要件・各 NFR より）
| 指標 | 目標 | 由来 |
|---|---|---|
| フレームレート | 一覧スクロール・ゲーム操作で **60fps** 維持 | NFR-U4/U6 |
| タップ確認再生の応答 | **< 0.1s**（お手本/選択肢のプレビュー発音） | NFR-U6-01 |
| 出題生成 | **O(choiceCount)** で体感遅延なし | NFR-U6-03 |
| コレクション読込/スクロール/再生/書込 | **体感即時（100 件で < 0.5s）** | NFR-U4 |
| 週替わりお題の表示 | **< 0.1s**（O(1) 週選択） | NFR-U5-01 |
| 録音処理 | 3秒固定・実時間内で完了、エフェクトはリアルタイム | NFR-03 |
| メモリ/GC | 加工音は**非保存・低GC**（再生時ピッチ）、`AudioBuffer` 再利用 | NFR-06 |
| 起動〜ホーム | 体感即時（軽量同期シーンロード） | NFR-U2 |

---

## Setup Performance Test Environment（準備）

### 1. 計測環境
- **実機**（必須）: 代表的なローエンド〜ミドル Android と iOS 各1台以上。エディタ計測は参考値。
- **ツール**:
  - Unity Profiler（`Window > Analysis > Profiler`）＋ **Development Build** で実機アタッチ
  - Frame Debugger / Memory Profiler（`com.unity.memoryprofiler` 任意導入）
  - オンスクリーン FPS 表示（`Statistics` / 簡易 FPS カウンタ）

### 2. テストデータ
- コレクション: **100 件**の保存音（`sounds/{id}.wav`＋`meta.json`）を用意（Scenario 2 反復 or テスト生成スクリプト）。
- ゲーム素材: 保存音あり／0件（fallback）の両ケース。

### 3. 計測パラメータ
- 各シナリオ **3 回**計測し中央値を採用。Development Build（Deep Profile は必要時のみ・値は割り引いて解釈）。

---

## Run Performance Tests（実行）

### 1. フレームレート（スクロール/ゲーム操作）
- Collection 一覧を 100 件で高速スクロール → Profiler で **CPU/GPU フレーム時間**と fps を記録。
- Game1 でドラッグ操作・演出再生中の fps を記録。
- **合格**: 60fps 維持（フレーム落ちが散発的で連続スパイクなし）。

### 2. 応答遅延（タップ→発音）
- Game1 の選択肢/お手本タップから発音開始までの体感を計測（Profiler のオーディオ/スクリプトマーカ、または録画のフレーム差分）。
- **合格**: < 0.1s。基準 `AudioClip` はゲーム開始時にキャッシュ済（再取得しない）。

### 3. I/O 時間（読込/保存/削除）
- コレクション初回読込（100 件の meta 集約 `ListSounds`）時間、保存（`SaveSound` 原子的 wav+meta）、削除時間を計測。
- **合格**: 100 件読込・各操作が体感即時（< 0.5s 目安）。破損 1〜数件混在でも安全にスキップし全体を止めない。

### 4. メモリ / GC
- Game1 で連続タップ/出題を繰り返し、GC Alloc の増加を Profiler で監視。
- 録音〜再生で `AudioBuffer` の再利用（都度 new しない）を確認。
- **合格**: 定常操作で GC スパイクが小さい。加工音の永続オブジェクトが増え続けない（非保存）。

### 5. 起動 / 画面遷移
- 起動〜ホーム表示、ホーム⇄各モジュール遷移の所要を計測（縦横両向き）。
- **合格**: 体感即時。回転時に SafeArea/レイアウトが崩れない。

---

## Analyze Performance Results（分析）
- **フレーム時間**: 実測 vs 60fps（16.6ms）。超過フレームの発生源（GC/描画/スクリプト）を Profiler で特定。
- **応答遅延 / I/O**: 実測 vs 目標。閾値超過の箇所を記録。
- **ボトルネック候補**: サムネイル生成（`CollectionSprites`）、meta 大量パース、リストの非仮想化描画、オーディオ初期化。
- **レポート**: `./Logs/` に Profiler キャプチャ/計測メモを保存。

## Performance Optimization（未達時の対応）
1. リスト描画: `SoundListView` の**仮想化**（可視分のみ生成）、サムネイル遅延ロード＆キャッシュ。
2. I/O: meta 読込のバッチ化・必要時のみ wav デコード（一覧はメタのみ）。
3. GC: 一時配列の再利用、文字列連結削減、`AudioBuffer` 再利用の徹底。
4. オーディオ: 基準 `AudioClip` の事前キャッシュ、`AudioSource.pitch` のみ変更（クリップ再生成しない）。
5. 変更後に該当シナリオを再計測して改善を確認。

---

## 備考
- 本アプリはネットワーク I/O・並行ユーザー・スループット概念が無いため、**負荷/ストレス/同時接続**の項目は N/A。代わりに**端末体感（fps・遅延・GC・I/O）**を性能の主指標とする。
